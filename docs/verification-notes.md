## 二、联调摩擦点(开发体验,应修让下次顺)

1. **LangGraph 客户端 LLM key 未装配**:文档说共享 key 放仓库根 `.env`,但根 `.env` 不存在,唯一的 key 孤悬在 `packages/feishu/.env`,起客户端得手动 source。→ 根 `.env` 统一放 `FOUNDRY_LLM_*`,或客户端启动兜底读 feishu/.env,并在 README 写明。
2. **本地默认头模式(未签名身份)**:安全类不变量(自审批)在头模式下可被 `x-foundry-user` 伪造绕过——实测同一台机器改个头就批了自己的单。→ 本地也能一键起 JWKS;README/脚本标注"头模式不能用来验证身份类不变量"。
3. **fixture ID(c001)vs 真 Twenty UUID**:测试命令不通用,拿 c001 打线上得 400。→ 脚本先 `list` 拿真 ID。
4. **部分路径硬编码、忽略 env**:`FOUNDRY_AUDIT_LOG` / `FOUNDRY_APPROVALS_LOG` 传了不生效(`serve.ts` 硬编码 `audit/foundry.jsonl`、`audit/approvals.jsonl`),导致找错文件、残留旧 pending。→ 读 env,或文档写明不可覆盖。
5. **demo 与线上差异大且无集中说明**:后端(fixture vs 真 Twenty)、鉴权(头 vs JWKS)、ID、数据都不同,一开始不清楚该测哪个。→ 加一页"demo vs 生产"对照表。
6. **改完 main ≠ 上线**:CI 无发布步骤,线上跑的是旧代码。→ 流程里明确"改完按 `DEPLOY-CHECKLIST` 重新部署才生效"。

## 三、发现的真实设计问题(产品,值得开单)

1. **[中] 网页收不到带外(飞书)审批后的状态**:`app.js` 无轮询/长连/推送,`server.py` 无服务端→网页通道;飞书批完执行结果只回飞书会话;刷新还丢历史(`threadId` 每次随机)。→ 网页在提交 pending 后即死胡同。修复方向:`/api/pending` 轮询面板 或 SSE/WS 推送 + `threadId` 持久化。
2. **[中] 审批"批了不执行、要发起人重放兑现"**:每个入口(LangGraph 自动重发 / 飞书 re-invoke / 裸 MCP host)各造一套兑现胶水,而裸 MCP host 的系统提示词还叫 LLM 别重试 → 没人兑现,单子批了不执行。修复方向:审批通过后服务端直接兑现,或提供独立"兑现工单"端点。
3. **[低·配置] 头模式是哑弹坑**:非 JWKS 也能启动、只打警告;误配进生产 = 审批安全静默塌。修复方向:生产环境强制 JWKS,否则拒绝启动。
4. **[记一笔] `approvals.jsonl` 仍未签名**:审批决策已补进签名审计链(#4),但这本账自身没防篡改,理想上该同链或做对账。

## 四、本地 ≠ 线上:怎么解决

**根因**:本地是手写 `FixtureBackend`(内存),线上是真 `TwentyRestBackend`(REST),两套实现会静默漂移——今天的分页 bug、UUID 400 都是漂移症状。

**业界最佳实践**:
1. **Dev/Prod Parity(12-Factor #10)**:三环境尽量同构——同后端类型、同鉴权模式。
2. **后端一致性测试(本仓已落地一步)**:`packages/adapter-twenty/src/conformance.test.ts`——同一套契约同时跑 `FixtureBackend` 与 `TwentyRestBackend`,外加 REST 漂移护栏(分页聚合 / 退款 404 fail-closed)。还原任一修复即亮红。**下一步**:扩到 contacts/accounts/opportunities 全部方法。
3. **测试金字塔**:单测走 fixture(快、纯);**集成测试走 Docker 里的真 Twenty**(`docker-compose` 已有)抓 REST 形状漂移;少量 E2E 打 staging。
4. **鉴权 parity**:本地也跑 JWKS(有 keygen),别在弱的头模式里验证身份类不变量。
5. **播种走版本化 seed 脚本**,本地(Docker Twenty)与线上同源 → 天然不分叉。

## 五、别直接改线上数据

- **生产不做写测试**:污染真实数据/审计/分析,且一般不可逆。
- **播种走幂等 seed 脚本,不手改记录**:"改数据 = 改脚本 + 重播"。
- **写测试打一次性环境**(staging / 本地 Docker Twenty)。
- **只用合成数据**,demo 里绝不放真实 PII。

本仓现状:线上 Twenty 是**手工播种**(`DEPLOY-CHECKLIST` §11 描述手动灌),无版本化 seed。→ 建议补一个幂等 seed 脚本(以 `FIXTURE_*` 为源),本地与线上共用。

## 六、数据升级方案(待拍板后实施)

**现状**:5 客户 / 5 联系人 / 5 商机 / 4 订单,够用但偏薄;三档退款已能演(cp01 ¥200 自动 / cp02 ¥8000 挂起 / cp05 频次),但订单金额全是大额。

**建议**(一次协同改 `fixtures.ts` + `eval/cases/twenty.yaml` + 快照):

**风险**:改数量会动 `expectRowCount` 断言(cn02=3、cn08=5、cn12=5 等)→ 需同步更新并重跑 eval。工作量中等,一起改一起验。
