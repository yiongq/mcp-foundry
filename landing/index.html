诚实边界

说清楚验证了什么、没验证什么

安全产品最怕过度承诺。以下边界与 README 保持同步:

✓两条真库链路都已验证:HR 对真实 OrangeHRM 5.7(只读 MySQL,本地 docker),CRM 对真实 Twenty(REST + Bearer)——都是演示数据口径,不是生产规模
✓线上 CRM 域连的是真实 Twenty(crm.yiongspace.com 读写真数据);HR 域线上仍走 fixture
✓体验链接的身份是配好的,不是登录来的——演示「同一网关、不同身份、行为不同」,不是登录系统
✓行级/字段规则只在 Guard 出口生效;绕过 Foundry 直连源系统管不到——源系统凭据只发给 Foundry
✓JWKS URL 模式默认可用性优先:端点持续故障期间吊销不生效,fail-closed 需自行开启 max-stale
✓ERP 仍是路线图;「多签发方」是能力,线上是单签发方口径

why

Three incidents → three capabilities

Safety doesn't rely on prompt discipline — structured rules are enforced at the guard layer.

Incident: a casual question returns a coworker's salary

Role → tool whitelist

Off-limits tools never appear in tools/list — instead of rejecting the call and explaining afterwards.

Incident: the model dumps whole rows — phones, salaries — into answers

Row filtering + field masking

Enforced at the guard's exit; unauthorized data never enters the context, so there's nothing to leak.

Incident: afterwards, no one can tell who asked what, when

Per-call audit trail

One JSONL line per call; params stored as hashes, never raw — the audit log doesn't become a second leak surface.

01
No calibration pass, no judge
≥90% agreement with a human-labeled golden set before a judge enters reports; new model = recalibrate. The judge can only add failures, never rescue them.
02
The dual track's value is discovery, not scores
On its first run the judge caught exit contamination invisible to hard assertions (a raw ZodError passthrough); the fix became a deterministic regression assertion.
03
The CI gate trusts hard assertions only
Any failed red-team case → CI exit 1; the LLM-judge costs money and depends on external APIs, so it stays out of the gate.

honest limits

What was verified — and what wasn't

Overpromising is the worst failure mode for a security product. These limits stay in sync with the README:

✓both real backends verified: HR against real OrangeHRM 5.7 (read-only MySQL, local docker), CRM against real Twenty (REST + Bearer) — demo-scale data, not production scale
✓The live CRM domain runs real Twenty (crm.yiongspace.com reads/writes real data); the HR domain stays on fixture online
✓Demo identities are pre-configured, not logged in — it demonstrates "same gateway, different identity, different behavior", not a login system
✓Row/field rules apply only at the guard's exit; bypassing Foundry to hit the source system directly is out of scope — source credentials go to Foundry only
✓JWKS URL mode defaults to availability-first: during a prolonged endpoint outage revocation doesn't take effect; fail-closed requires opting into max-stale
✓ERP is still roadmap; "multi-issuer" is a capability — the live deployment is single-issuer
